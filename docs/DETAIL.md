# ASAR 壳桥 · 插件详情

## 这个插件做什么

DSH 桌面版的程序本体打包在安装目录的 `resources/app.asar` 里。Host 插件运行在一个独立的
Node 子进程里，从结构上够不到 Electron 主进程的托盘、通知、窗口。要让插件能扩展这些界面，
必须让主进程里有一小段代码去加载一个外置文件。

本插件做的就是这个"接上一小段"：

1. 在 `app.asar` 的 `lib/main.js` 里，**官方托盘那段代码（本机量出来是 1,253 字节）一个字节都不动**，
   在它后面插入一段**本插件自己的**区域（默认 **16,384 字节**），用来放"委托外置桥"的实现；
2. 把外置桥文件放进 `resources/app.asar.unpacked/dsh/tray-bridge.js`；
3. 提供一个 Host 服务，让其他插件通过它使用这些能力。

**布局** 这样做的代价是：插入会让 `lib/main.js` 变长**正好一个区域长度**、它后面 29 个条目整体后移
同样的字节数；当前预留 16,384 字节，所以归档比官方原档大 16,384 字节（rc.3 上实测是
209,021,953 → 209,038,337 字节）。换来的两件事：这一段区域**多长由插件自己定**，不再被托盘槽位卡住；
**卸载不再需要那份约 209 MB 的备份**——反向算回去就能逐字节还原成官方原档。

0.1.x 时代用的是「等长替换」：把那 1,253 字节原地换掉，字节数完全不变，所以归档大小、目录头、
所有 offset 都不变，代价是补丁必须挤进 1,253 字节、而且**卸载必须有备份**。那台机器如果是那样装的，
新版会在第一次「安装」时**自动迁移**到当前布局（迁移要用那份备份；备份已经没了就拒绝，并提示按
`docs/RESTORE-STOCK.md` 手工换回官方原版。详见下面「卸载与还原」）。

两种布局插件都认得、都能还原。命令行 `node scripts/install.mjs --status --root <安装目录>` 会打出
一行明确的**布局**：`官方原样` / `槽位内补丁 0.1.x` / `官方槽位 + 自有区域 0.2.0` /
`重复安装（需还原）` / `无法识别（拒绝写入）`（`--json` 里是 `layout` 字段）。
设置页那张卡片上已经有一行「**布局**」（`client.js` 读 `snapshot.layout`，文案在
`locale/zh.json` 与 `client.js` 的内置表里），所以 split 布局与 0.1.x 布局在界面上就能分开，
不必再去跑命令行。

## 能力范围

本插件做**安装链路 + 托盘贡献 + 通知 + 窗口 + IPC 通道**：

- 插件加载时**只读检测**：asar 里有没有我们的区域（或 0.1.x 的槽位补丁）、桥文件在不在。
- 没有就弹**安装页**：输入安装目录、自动搜索、浏览目录、安装。
  （只有在你**这次运行**里点过「稍后」才会暂时不弹；重启 DSH 后会重新问。
  设置页的「重新打开安装页」可以马上把页面叫回来。）
- 安装时**先备份** `app.asar`（同目录，`app.asar.<时间>.v<DSH版本>.bak`）——如果那里已经有一份
  官方原样的备份（同体积、同摘要），就直接用它，不再重复复制一份。然后再插入区域、放桥。
  （备份是给"手术做到一半崩掉"这种情况留的后路，不是卸载必需的。）
- 装完提示**需要重启 DSH**；如果装了 dsh-power，给一个快速重启按钮。
- 设置页有**卸载 / 还原**：确认依赖插件已关闭后，按当前布局还原（见下文），再删掉桥文件。
- 其他插件可以通过 `asarShell.contribute()` **往托盘加菜单**，并通过 `events(cursor)` 读回点击。

## 安装页怎么用

1. 插件第一次加载时，检测不到桥 → 自动弹出安装页。
2. 目录栏可以手填，例如 `<DSH安装目录>`；
   或点**自动搜索**：插件会扫描每个盘**第一层**里名字像 DSH 的目录
   （`dsh` / `ds` / `deepseek` / `deepseekharness` / `dshd` / `deepseekharnessdesktop`，忽略大小写，
   也认 `-` / `_` 变体），再用 asar 里的 `package.json` 确认它真的是 DSH 桌面版。
3. 也可以点**浏览…** 用系统"选择文件夹"界面挑目录。
4. 点**安装**。写入前会做一次**版本检查**，结论分三级：

   - **已验证**：这个 DSH 版本登记过，且托盘那段代码（以及我们自己的区域）的长度和内容
     都与验证过的一模一样 → 直接装；
   - **未验证**：看起来是官方原样，但这个版本还没跑过（版本号没登记 / 长度变了 / 内容变了）
     → **可以装**，页面上列一条「版本检查」逐条说清新在哪里，并请你装完确认托盘菜单正常；
   - **不能装**：官方 `lib/main.js` 里少了补丁要用的某个名字，或托盘那段代码被别人改过、
     版本认不出来 → 安装按钮变灰、原因写在按钮提示上，文件一个字节都不动。

   安装做什么，取决于磁盘上现在是哪一种：

   - **官方原样**：备份 → 插入 16,384 字节区域 → 回读校验 → 放桥 → 写记录；
     首次约有一次 1 MB 的数据搬移（耗时未留存计时记录，不要当实测引用）；
   - **0.1.x 的槽位内补丁**：**自动迁移**——先用备份把官方字节写回槽位、确认回到「官方原样」，
     再做上面那条；备份已经不在了就**拒绝**，并让你按 `docs/RESTORE-STOCK.md` 手工换回原版；
   - **已经是当前布局**：什么字节都不搬，只重装桥、重写记录（区域内容陈旧时原位改写那 16,384 字节）；
     区域**长度**与当前预留不同（旧构建留下的，例如 8 KiB）时，同一次「安装」会先退回官方字节、
     再插入 16,384——完成后的几何与从没装过的机器一致；
   - **外来修改 / 认不出来 / 两种布局叠在一起**：拒绝，并说明是哪一种。

## 卸载与还原

设置页 → 插件 → 本插件 → 红底「卸载 / 还原 asar…」：

- 弹窗问「是否已经关闭了依赖 dsh-asar-framework 的插件？」
- 选**否** → 不会继续，提示你先去插件页禁用那些插件（因为它们正靠桥工作，直接拔掉会让它们在半路失效）。
- 选**是** → 按布局还原：
  - **当前布局的自有区域**：把插入的那段区域（长度按文件里的几何量，当前是 16,384 字节）
    连同后移的数据整体退回去，**不需要备份**，产出的就是官方原档；
  - **0.1.x 的槽位内补丁**：用备份把官方字节覆盖回槽位；
  - **本来就是官方原样**：什么都不做，只报一句「无需还原」。

  然后删掉桥文件，提示"先禁用本插件再重启 DSH"。本次运行不会再弹安装页。

## 必须知道的限制

- **改完必须重启 DSH 才生效。** Electron 启动时就把 asar 读进内存了，运行中改字节不会重新加载代码。
- **备份占空间，但不会重复占。** 一份备份约等于 asar 大小（本机 209 MB）；已经有的会被校验后复用，
  不重复复制。同目录最多留 **5 份**，再旧的会被清掉（安装记录指名的那一份永远不清）。
  备份没了也能救：见 `docs/RESTORE-STOCK.md`（用官方安装包里的原版 asar）。
  **当前布局的卸载不需要备份**；只有 0.1.x 装的机器（官方字节已被替换）才必须靠备份。
- **首次安装会搬一次数据**：约 1 MB（耗时数字已从文档撤下——没有留存的计时记录）；
  之后每次安装都不搬数据（区域已在），区域字节陈旧时只原位改写那 16,384 B。
  **归档比官方原档大预留的 16,384 字节**（rc.3 实测 209,021,953 → 209,038,337 字节）。
  旧构建装过的机器（例如早年那版 8 KiB 区域）点一次**安装**就会在同一次操作里
  先退回官方字节、再插入 16,384，结果与从没装过一样。
  区域最多能预留 **151,494 字节**，再多就会让目录头变长、卸载无法逐字节还原，所以插件会拒绝。
- **改 asar 不是原子操作**：插入过程如果正好崩在"搬数据"与"更新目录"之间，归档会处于读不对的状态，
  需要靠那份备份恢复。这也是首次安装仍然先写备份的原因。
- **只支持 Windows x64 的 DSH 桌面版。** 不绑定某个具体 DSH 版本：每次安装都现场做版本检查
  （见上面三级判定），托盘那段代码的长度是**量出来的**而不是写死的。
  真正会拦住的只有一种情况——官方主程序里少了补丁要用的名字，那会让桌面版启动即崩。
- **桥不是沙箱。** 桥运行在 Electron 主进程里，权限与 DSH 相同；能替换它的人也就能改安装目录。
  它只防"协作型插件互相踩踏"，不防同权限的恶意改动。
- **已经做到：托盘菜单 + 通知 + 窗口 + 一条真 IPC 通道。** 通知（`asarShell.notify()`）
  与窗口（`asarShell.channelSend({channel:'window'})`）都已实现：前者写 `notify.json`
  由桥轮询后弹出，后者通过真 IPC 让主进程**当场**开一个同源窗口。主进程的消息校验器
  也确实被扩展了：注入区域接受并处理保留类型 `dsh-asar-bridge`，由我们自己的 dispatcher
  分发（`lib/asar/patch-body.js` 的 `IPC_BODY`）。
- **仍然没有的**：HTML 面板 / 扩展运行时 / 每个插件独立的 `session` 或自定义 protocol；
  窗口的文件通道写半身（`window.json`）没有接上；通知与窗口的真机行为未在真实桌面上验证过。
