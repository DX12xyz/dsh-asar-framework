# 安全边界（SECURITY.md）

## 一句话

本插件**不是安全沙箱**。它只防「协作型插件互相踩踏」，不防「同权限的恶意改动」。

## 谁能在哪里做什么

| 角色 | 能碰什么 | 不能碰什么 |
| --- | --- | --- |
| Host 半身（Host 子进程） | 读 asar、状态目录读写、调安装/还原 CLI、写 `menu.json` | 不直接创建托盘/通知；不常驻改 asar |
| 外置桥（Electron 主进程） | 渲染托盘菜单、写事件与诊断文件 | 不 `new Tray`、不 `app.quit()`、不 `tray.destroy()`、不改 asar |
| 安装 CLI（一次性进程） | 备份 asar、**在官方托盘槽位之后插入自有区域**（首次会搬移它后面的数据）、装桥、写记录 | 不改官方槽位的字节、不改被搬移条目的内容、不重打包 asar |

## 威胁模型

1. **同权限用户/进程可以改任何东西。** `app.asar` 是普通文件，任何能写安装目录的进程都能改它。
   本插件能做的是**检测**（分类成 `foreign`/`unknown` 并拒绝覆盖），不是**阻止**。
2. **桥文件可被替换。** 它在 `app.asar.unpacked` 里，不在 asar 目录头中。替换它的人等于拿到
   主进程代码执行。安装器会记录桥的 sha256 并在状态里显示，但不会持续防篡改。
3. **状态目录可伪造。** `<DSH_HOME>/dsh-asar-framework/` 里的 `menu.json`、`events.jsonl`
   等是普通文件，同权限可写。它们只影响"显示什么"，不构成提权。**`menu.json` 尤其如此**：
   它是托盘菜单的输入，任何能写这个目录的进程都能往里塞条目（包括图标/菜单文字/子菜单结构）。
   插件在写入口做了限额与形状校验（见 `TECHDOC.md` §19.7），但那是"帮作者少犯错"，不是"防恶意"——
   同权限的进程可以绕过注册表直接改文件。
4. **备份是本机最方便的原样来源，但不是唯一来源。** 还原时优先用安装记录指名的那份
   `app.asar.*.bak`（安装时写、之后只读），找不到才用最新的；0.1.x 的槽位内补丁**只**能靠备份
   还原。另一条不依赖本机历史的来源是**官方安装包里的原版 asar**，手工流程见
   `docs/RESTORE-STOCK.md`。**当前的 split 布局是第三种**：它的退装是从文件几何反算出来的
   （`shrinkRegion`），不需要备份也能逐字节回到官方原档。

## 写入边界：官方槽位不动，但"槽位之外一个字节都不碰"不成立

0.1.x 时代只改 `lib/main.js` 内固定 1,253 字节区间，不改变文件长度、目录头、任何 offset。
**现在不是这样**，必须如实写明：

- **官方 1,253 字节的托盘槽位仍然逐字节不动**（`779,389` 起、摘要仍是 stock 的
  `4bc10e1e…ce64`，写完由 `verifySplit` 用 `plan.slotShaBefore` 逐字节复核）；
- **但我们的区域是插入进去的**，所以 `lib/main.js` 从 848,505 字节长到 864,889 字节（+16,384），
  它**后面**的 29 个条目（993,917 B）与 `lib/main.js` 自己的 67,863 B 尾部
  **在文件里整体后移 16,384 字节**（一共 1,061,780 B 被复制到新位置），30 个目录字段
  （29 个 `offset` + 1 个 `size`）被改写。归档从 209,021,953 变成 209,038,337 字节。
- 所以准确的表述是：**官方槽位的内容没被改；区域之外的内容也只是被平移，没有被改写。**
  "被平移"与"没碰"不是一回事：任何按**绝对字节偏移**记录外部事实的工具（外部快照、
  按偏移写的第三方补丁、以文件大小做判断的脚本）都会看到差异。
- **目录头的长度被保住了**（5,669,961 B 进、5,669,961 B 出），`integrity.blocks` 一个都没动。
  这条不是审美要求：它是"退装 == 官方原档"的**充要条件**，也是本插件拒绝
  超过 151,494 B 预留的唯一原因（再多一个字节，`lib/main.js`.`size` 就进位、目录头就变长，
  那时要么改 `integrity.blocks`、要么放弃可逆性，两者都不能接受）。

**为什么仍然值得**：插入是**一次性的代价**（约 1 MB 搬移、211–580 ms），换来的是"官方槽位原样"
与"退装不需要 209 MB 备份"；0.1.x 的等长替换则把能力永久锁在 1,253 字节里、并且退装依赖备份。

**这个代价不是原子的**，必须一并说明：`growRegion` 的顺序是"EOF 追加 → 从后往前搬尾部 →
写长大的 `lib/main.js` → **最后**写目录头"。在"搬完"与"写完目录头"之间崩溃，文件处于
**旧目录已经解释不了**的状态（新目录还没落盘，旧目录指向被覆盖的区域），此时唯一的恢复路径是
那份**基线备份**。所以首次安装**仍然先写备份**——不是因为退装需要它，而是因为手术中途崩掉需要它。

## 失败策略

全部 fail-closed：

- 官方 `lib/main.js` 里缺了补丁依赖的某个名字 → 拒绝写入，文件不动（这是唯一会让桌面版启动即崩的情况）；
- 槽位被别人改过、或版本认不出来 → 拒绝写入，文件不动；
- **两个布局叠在一起**（0.1.x 的槽位内补丁 + 当前的自有区域）→ 判 `foreign` + `doubleInstall`，
  拒绝写入并给出还原路径。这不是"别人干的"，是本插件自己两次安装叠出来的，但"拒绝再次覆盖"
  的结论一样；
- **计划会让目录头变长**（预留超过本归档实测上限，本机 151,494 B）→ 拒绝，文件一个字节都不动；
- **手术前置条件不成立**（`lib/main.js` 之后的数据有空隙 / 未到 EOF / 与 `lib/main.js` 重叠 /
  目录头不能逐字节往返序列化）→ 拒绝。搬一个带空隙的尾部无法逐字节还原，所以宁可拒绝；
- 版本没登记、槽位长度或内容与验证过的不一致 → **可以写**，但页面/CLI 会列出一条警告
  （拒绝的判据取最保守的那一条，其余降级成警告：装错的代价比多问一句大得多）；
- 备份失败 → 不写 asar；
- 桥复制失败 → 报告"asar 已写入、可用 `--restore` 回退"并给出备份路径（**不是**静默继续）；
- 运行中文件被锁 → 同尺寸原位写；跨尺寸直接拒绝并提示先退出 DSH；
- **迁移 0.1.x 时找不到基线** → `ENO_BACKUP` 拒绝，绝不"在一个不再原样的槽位后面再叠一段区域"；
- **退装时反向手术失败或还原出的摘要与记录不符** → 不声称成功，回落备份并把两边的摘要写进结果；
- 桥的任何异常 → 回退官方三项菜单，托盘永远可用。
